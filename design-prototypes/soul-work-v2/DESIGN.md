# Soul Work-first V2 原型交接

## 定位

- 设计基线：Stitch V2，未采用 huashu-design V3。
- 产品主路径：提出目标 → 匹配专家 → 确认计划 → 执行工作 → 审阅结果。
- 一级导航：新工作 / 工作 / 项目 / 自动任务 / 专家 / Chat，设置置底。
- 原型入口：`index.html`，无依赖、可直接用浏览器打开。
- 本目录只用于视觉与交互验收；HTML、CSS 和 JavaScript 不直接合入 Electron / React 正式工程。

## 视觉系统

### 设计原则

1. 工作台优先：工作目标、执行状态和成果始终高于聊天装饰。
2. 中性桌面质感：按钮、表单和信息层级参考 Codex / Claude 桌面端的克制表达。
3. 品牌轻量出现：Soul 粉色只用于品牌标识、选中线和少量状态反馈，主操作使用中性深色。
4. 信息可读：可见文字下限为 12px；按钮和导航 13–14px；正文 14–15px。
5. 状态可解释：低风险自动执行，中风险确认一次，高风险在操作发生前单独确认。

### 控件规则

- 主按钮：深色实底、36px 高、7px 圆角。
- 次按钮：白底描边、34px 高、7px 圆角。
- 表单：最小 34px 高，焦点使用中性描边，不用高饱和光晕。
- 卡片：8–10px 圆角，弱阴影或无阴影，依靠分割线建立层级。
- 右侧工作栏：默认关闭；通过标题栏按钮或 `⌥⌘B` 打开。
- 全局搜索：按钮、`⌘K` 或 `⌘P` 打开，按页面名称优先排序。

## 关键流程

### 新建任务

新建 → 输入目标并选择项目/专家/权限 → 开始任务 → 进入项目下的同一条对话 → 在消息流中查看计划、进度、待确认事项和结果。

### 缺少专家

任务详情 → 重新匹配专家 → 展示能力缺口与空知识库 → 创建项目临时专家 → 补充知识 → 运行五类测试 → 回到原对话恢复任务。

### 对话设为任务

选择历史对话 → 在当前对话中设为任务 → 原消息、项目上下文和附件保持不变 → 在同一消息流中确认计划并开始执行。整个过程不复制对话，也不创建第二条任务记录。

### 任务与对话层级

- 一级「任务」用于跨项目查看执行中、待处理、草稿和已完成任务。
- 任务本质上是项目下具备执行状态的对话；项目侧栏中的任务和普通对话共用一个列表。
- 普通对话不显示任务状态；设为任务后才显示草稿、执行中、待确认或已完成。
- 旧三栏任务页仅作为「执行详情」回退，不再承担主要消息流。

### 自动任务

创建或编辑规则 → 选择任务 / 对话类型 → 启用或手动触发 → 查看触发历史 → 打开独立任务对话或普通对话提醒。

### 高风险操作

删除项目、重置本地数据、外部发送等 → 展示计划和影响范围 → 单独确认 → 原型仅反馈，不产生真实副作用。

## 验收记录

- `1440×900`：7 个一级页面无横向溢出。
- `1280×800`：7 个一级页面无横向溢出，核心操作无遮挡。
- 可见文字下限：12px。
- 静态按钮：191 个；未命名按钮 0 个；无绑定候选 0 个。
- 纯提示占位按钮：0 个。
- 设置页：12 / 12 可切换。
- 专家功能：15 / 15 可打开。
- 浏览器控制台：无错误日志。
- HTML 脚本语法检查通过；静态 DOM ID 无重复。

### 任务与 Chat 合并验收（2026-08-02）

- 一级「任务」总览可打开 4 种示例状态，并进入对应项目对话。
- 项目页、专家页、新建入口和自动任务结果均回到统一任务消息流。
- 普通对话可原地设为任务，升级前后侧栏记录数量不变。
- 草稿和等待确认状态可在消息流内开始或恢复执行；任务详情可回退旧三栏页。
- `1440×900` 与 `1280×800` 均无页面横向溢出、任务卡内部滚动或输入框遮挡。

## 正式开发边界

- 原型中的数据和运行结果均为交互示例，不代表真实专业结论或测试成绩。
- 正式开发继续使用现有 Electron / React / TypeScript 架构。
- 正式实现必须从主进程读取安全配置、文件权限和真实运行状态。
- 渲染层不得接触凭据或绝对文件路径。
- Stitch / HTML 导出代码只用于视觉参考，不直接复制进正式产品。
